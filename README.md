# سوقلي — Sawqli

منصة تسوق عربية متجاوبة (RTL) تجمع الإلكترونيات والأجهزة المنزلية وقطع غيار السيارات والأزياء والأدوات والمنتجات الرقمية والخدمات.
تبدأ بكتالوج من **90 منتجًا**، و**68 قسمًا رئيسيًا** (تشمل الأزياء، المنزل، التجميل، الألعاب، السيارات،
المستلزمات الطبية ومخبرية، المنتجات الرقمية والمستعملة...)، و**8 عملاء**، و**14 طلبًا** بكل حالاته،
و**73 تقييمًا**، مع لوحة مركزية لإدارة الصفحات والأقسام والهوية وروابط الواجهة.
كل البيانات تُحفظ في `localStorage`، لذا يعمل التطبيق بالكامل بدون إنترنت.

مبنية حسب الوثيقة التنفيذية `design md` (تطبيق العميل + لوحة الإدارة).

## التقنيات

| العنصر | التقنية |
| --- | --- |
| اللغة | TypeScript |
| الواجهة | React 19 + Vite 8 |
| التنسيق | Tailwind CSS v4 (CSS-first، بدون ملفات إعداد) |
| التنقل | React Router 7 |
| الأيقونات | lucide-react |
| الخط | Cairo Variable (مضمّن محليًا عبر `@fontsource-variable/cairo`) |
| الصور | كل الصور SVG مولّدة داخليًا (`src/lib/artwork.ts`) — لا تحتاج شبكة |

## التشغيل

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # بناء للإنتاج إلى dist/
npm run preview    # معاينة بناء الإنتاج على 4173
npm run typecheck  # فحص أنواع TypeScript
npm run smoke      # اختبار تصيير لكل المسارات (React + jsdom)
npm run flows      # 12 تدفقًا حرجًا، تشمل CMS والتسليم الرقمي والشراء الكامل
npm test           # typecheck + smoke + flows
```

## النشر على Vercel

- Framework Preset: **Vite** (أو Other) — أمر البناء `npm run build`، ومجلد الإخراج `dist`.
- ملف `vercel.json` يحتوي على إعادة توجيه SPA لكل المسارات إلى `index.html` + ترويسات تخزين مؤقت للأصول.

## طبقة الخدمات (`src/lib/service.ts` + `src/store/ServiceContext.tsx`)

بدل التعامل المباشر مع التخزين المحلي، تمر كل عملية كتابة حساسة عبر طبقة خدمات موحّدة:

- تتحقق من الاتصال قبل التنفيذ وتُرجع خطأ `OFFLINE` عند انقطاع الشبكة.
- تُحاكي زمن استجابة واقعيًا (140–1200ms حسب نوع العملية) فتظهر حالات التحميل فعلًا.
- تُرجع نتيجة موحّدة `{ ok, status, data, error, code }` مع رسائل عربية واضحة.
- تتكفّل بالآثار الجانبية المترابطة تلقائيًا:

| العملية | الآثار الجانبية |
| --- | --- |
| `placeOrder` | التحقق من المخزون → خصم الكميات → زيادة المبيعات → تسجيل استخدام الكوبون → إشعار للعميل + إشعار للإدارة |
| `cancelOrder` | إعادة الكميات للمخزون → تصحيح المبيعات → إرجاع استخدام الكوبون → تحديث حالة الدفع → إشعاران |
| `updateOrderStatus` | إعادة بناء الخط الزمني → تحديث حالة الدفع عند التوصيل → إشعار للعميل |
| `submitReview` | تعديل تقييم سابق إن وُجد → إعادة حساب متوسط المنتج → إشعار للإدارة |
| `validateCoupon` | فحص التفعيل، النافذة الزمنية، حد الاستخدام، الحد الأدنى، والجمهور المستهدف |

### تفاصيل مهمة
- **حالات الجلسة:** تنتهي جلسة العميل بعد 30 دقيقة من تسجيل الدخول، ويمكن محاكاة الحالة مباشرة من
  `الإعدادات → إعدادات تقنية → اختبار حالات الواجهة`.
- **الشعار والأيقونة:** يُرفعان من `الإعدادات → الإعدادات العامة` ويُطبَّقان فورًا (الشريط العلوي، لوحة الإدارة، تبويب المتصفح).
- **الشحن/الضريبة:** محسوبان فعليًا في `src/lib/pricing.ts` ويُستخدمان في السلة وإتمام الطلب والطلبات.
- **الدفع:** أُزيلت طرق الدفع من واجهة العميل (الطلب عبر واتساب)، وتبقى إعداداتها في لوحة الإدارة فقط.
- **تصدير البيانات:** من جداول المنتجات والطلبات والعملاء (CSV يفتح في Excel)، واستيراد المنتجات من CSV.
- **حملة «عروض اليوم»:** نافذة زمنية تُجدَّد تلقائيًا عند انتهائها (مثل أي متجر يدير حملات متعاقبة)،
  ويمكن ضبطها يدويًا من `الإعدادات → الإعدادات العامة`.
- **إصدار التخزين:** تُحفظ البيانات تحت بادئة مُصنَّفة بالإصدار (`STORAGE_VERSION` في `src/store/persist.ts`).
  رفع الإصدار يُعيد تحميل البيانات الأولية للمتصفحات القائمة بدل بقائها على نسخة قديمة.

## الاستجابة (Responsiveness)

- **تطبيق العميل** يظهر بإطار عريض ثابت (`max-width: 480px`) ومتوسط أفقيًا على الشاشات الكبيرة حسب الوثيقة،
  ويتكيّف داخليًا من `320px` فأعلى: شبكة منتجات بعمودين، شرائح أفقية، وأشرطة إجراءات ثابتة تحترم `env(safe-area-inset-*)`.
- **لوحة الإدارة** كاملة الاستجابة: شريط جانبي ينزلق على الجوال وثابت على `lg`،
  وتتحوّل كل جداول البيانات (الطلبات، المنتجات، العملاء، التقييمات، الكوبونات، أحدث الطلبات)
  إلى **بطاقات مخصّصة للجوال** بدل التمرير الأفقي.

## الأداء

- **Code Splitting:** كل شاشات لوحة الإدارة + الشاشات الثانوية في تطبيق العميل تُحمَّل عند الطلب،
  فالحزمة الأولى للمتجر ≈ 96KB مضغوطة، ولوحة الإدارة كاملة لا تُحمَّل إلا عند فتح `/admin`.
- الصور كلها SVG داخلية (لا طلبات شبكة)، والخط Cairo مُضمَّن محليًا.
- كل البيانات محلية في `localStorage` — لا انتظار لأي API.

## ملاحظات مهمة

- **لا يوجد خادم:** المصادقة، الطلبات، الكوبونات، الإشعارات... تُدار محليًا عبر طبقة الخدمات. زر «إعادة تعيين بيانات المتجر»
  في `الإعدادات → إعدادات تقنية` يعيد كل شيء لحالة البداية (الكتالوج الجاهز).
- **حالات عامة مطبّقة:** شاشة تحميل مع انتقال لشاشة خطأ بعد 10 ثوانٍ، شريط انقطاع الاتصال (أحمر/أخضر)،
  تنبيه انتهاء الجلسة (يظهر بعد 30 دقيقة من تسجيل الدخول، ويمكن إنهاء الجلسة من `الإعدادات → إعدادات تقنية`)،
  صفحة 404، وإشعارات Toast بأربعة أنواع (تختفي بعد 3 ثوانٍ، أو 5 مع زر إجراء).
- **تخصيص الهوية:** الألوان والنصوص قابلة للتعديل من لوحة الإدارة وتُطبَّق فورًا على التطبيق.
- **الهوية اللونية:** اللون الأساسي بنفسجي «#7c3aed» كما في الوثيقة (وثانوي أزرق «#2563eb»)،
  مع 5 أنظمة ألوان جاهزة في `الإعدادات → هوية المتجر`.
